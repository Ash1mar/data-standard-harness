# 暂缓实施的业务修复方案

本轮范围：恢复环境、同一个 MCP 接入 A/B、恢复日常 Harness Web 模型桥、真实型钢 B 与合成文本 A 验证。
以下业务问题保留原实现，不将 MCP 接入成功描述为人工审批或生产验收通过。

## 1. 人工决策执行

位置：`backend/tools/model_synthesizer.py`、`requirement_analyst.py`，以及 `main.py` 中的决策字典。

现状：合成函数未消费冲突决策；建议生产端使用 `inferred_value/llm_definition`，消费端读取 `value`；
`pending/manual` 未成为确认后交付的阻断条件。同名属性的决策键也缺对象类维度。

方案：

1. 统一建议结构：`field_key={class_name, attribute_name}`、`suggestion={data_type,constraint,unit,definition}`、依据、置信度。
2. 显式实现 `adopt/answer/pending/reject`；冲突动作单独实现并保留原值、新值和选择依据。
3. 草案允许包含未决项；确认后的交付和入库必须检查未决项，不能只依据名称、类型存在。
4. 决策按运行和输入快照持久化；输入变化后失效。旧字段名键只在唯一匹配时兼容。
5. 前端和 Harness 都读取同一份后端决策记录，模型只能建议，不能把自己标成审批人。

验收：采纳后真实改变字段；待定和转人工无法形成“已确认”产物；同名跨类属性互不覆盖；重启保留决定。

## 2. 上游产物关联

位置：`standard_generator.load_final_model/draft_from_mode_b/_assemble`、`model_synthesizer.commit_final_model`、评测与导出。

现状：P6 读全局 `latest.json`；可能给旧模型写入当前文件名；标准 ID 仅精确到秒。
本次真实 B 确认：评测器读取指定 P6 文件，但组装报告时遗漏 standard_id。MCP 已增加响应关联状态提示，
未改动评测器。草案完整类清单与导出均为 23 类，其中有属性的类为 12 类；两种计数口径须区分。
后续修复应将原标准 ID、输入摘要和评测范围完整保留到报告中。

方案：

1. 生成唯一 `run_id` 和输入内容摘要，记录 D0 版本、D4 版本及模型配置摘要（不含密钥）。
2. P5 返回明确 `final_model_id/path`；P6 只接受该产物引用，并校验运行及输入摘要。
3. 标准 ID 使用日期、时间和 UUID；使用原子写入，保存失败必须返回失败。
4. `latest` 仅供界面浏览，不作为跨阶段运行的隐式输入。
5. 评测和导出始终使用同一 `standard_id`；标准来源、评测范围和指标口径随报告保存。
6. 引入后端单任务执行约束，统一网页和 MCP 的并发写入行为；中断后状态为待核实，避免自动重跑。

验收：切换输入后旧产物不能继续生成；同秒多次生成不会覆盖；重启可恢复上游引用；评测与导出对应同一份标准。

## 3. 本轮的有限约束

- MCP 只允许本机 HTTP 后端，要求实时模式并拒绝回放；不注册入库、删除、恢复历史等工具。
- 模式 B 生成工具显式调用现有 P5 保存后再调用 P6，后续使用刚返回的标准 ID。
- 上述调用顺序不能替代正式的运行/产物关联修复。现阶段请单任务使用，计算过程中不要切换上传数据。
- 所有生成结果标记为草案。MCP 返回的 `draft_only` 不改变原有业务审批逻辑。
- A 选择候选时沿用旧 approve 端点，显式记录“技术草案选择，不代表人工批准”；未修改人工决策执行逻辑。
- 回放、模拟模型测试、真实模型测试分别说明。合成样例得分只验证集成链路，不代表业务准确率。
