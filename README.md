# 核电数据标准智能治理智能体（双模式）

面向核电 EPC 数据标准治理的可演示智能体原型。以「双知识底座 + 双模式流水线」为核心，支持**现场上传数据 → 解析 → 抽取 → 建底座 → 梳理/转化 → 生成标准**的完整闭环，全流程可视化、可追溯、可人工门控。

- **前端**：Vue 3.5 单页应用（无构建步骤），依赖已本地化，**断网可演示**
- **后端**：FastAPI + SSE 流式事件
- **大模型**：P2 / P4 / P5 / P6 四个环节真实调用（任意 OpenAI 兼容接口）；**没有 key 也能跑**，自动回落规则并在界面标注
- **启动后访问**：<http://127.0.0.1:8123>

---

## 1. 两种工作模式

| 模式 | 名称 | 起点 | 解决什么问题 | 主要面板 |
|---|---|---|---|---|
| **A** | 发现式梳理 | 已有建模集 + 待梳理的业务文档（如工作手册、管道等级表） | 从存量文档中发现**尚未被标准覆盖**的对象类与属性，评估新颖性，立项生成标准草案 | P1 → P2 → P3 → P4 → P6 |
| **B** | 需求转化 | 业务人员填写的需求文件（含空缺、模糊、冲突） | 把**不完整的需求**补齐、澄清、与已有标准匹配，合成可直接导入 EDM 的数据模型 | P1 → P2 → P3 → P5 → P6 |

> **两个模式的知识底座完全独立、不共用任何节点。** 同一批对象类在 A 模式可能是评测答案、在 B 模式是建模集，系统按模式硬隔离，禁止交叉取数（见第 6 节）。

## 2. 快速开始

### 2.1 环境要求

- Python **3.11 及以上**（推荐 3.13）
- 无需 Node.js、无需前端构建；**主流程不依赖联网**（大模型为可选增强，需能访问模型服务）
- 浏览器：Chrome / Edge 最新版

### 2.2 安装与启动

**Windows（PowerShell 或 CMD）**

```bat
cd /d C:\work\data-standard-agent
python -m venv .venv
.venv\Scripts\activate
pip install fastapi uvicorn python-multipart openpyxl pdfplumber python-docx
python backend\main.py
```

> **pip 不可用时（内网 / 代理返回 403）**：本机已内置离线依赖包，改走本地安装：

### 3.1 P7 怎么用

1. 切到 P7，选模式 → 点「运行评测」。每种模式只有一套「当前数据集」，不需要选组。
   - 生成侧只读 `输入/`，答案侧只读 `预期输出/`，一一对应。
   - 右上「对照：P6 产物」仅用于排查，**不得作为验收数字**。
2. 指标分四块：**对象类层 / 属性层 / 关系层 / 合计**，各含「生成准确率」与「覆盖率」；group1 的预期输出只有对象类表，属性层显示 N/A。
   **关系层单列**（比的是 `(类型, 头, 尾)` 三元组，量纲与"行"不同，不并入合计）；合计只含对象类 + 属性，面板会注明。
   面板顶部会显示实际读到的输入文件与解析质量（`ready` / `degraded`）。
3. 四个数一起看：

| 指标 | 计算方式 | 怎么读 |
|---|---|---|
| **生成准确率** | exact ÷ 生成行数 | 生成出来的行有多准（主指标）|
| **标准覆盖率** | exact ÷ D3 作用域行数 | 标准答案被覆盖了多少 |
| **字段级准确率** | 一致字段单元 ÷ (已对齐行 × 4) | 行对上了，字段填得对不对 |
| **F1** | 严格口径 | 精确率与召回的综合 |

4. 点判定 chip 筛选明细：**exact**（完全一致）、**partial**（有字段差异）、**missing**（漏生成）、**extra**（多生成）。
5. 下载 `test_report.md` 与 `match_detail.csv`。CSV 每行带 `matched_by`（按编码/名称/语义匹配）、`similarity`、`diff_fields`，评委可逐行审计。
6. 跑完可点「归档本次梳理」，把这次数据、三表、报告打成一份只读快照。

### 3.1.1 历史梳理存档

- **入口**：顶栏右侧「历史存档 · N」（任何面板可开）；P7 底部「归档本次梳理」。
- **归档内容**：输入、预期输出、三表 xlsx、评测报告与明细、`meta.json`，整体自包含（不依赖原路径）。
- **只读**：不进图谱 / RAG / 缓存，不改变「上传 > 内置」的取数优先级；唯一回到主流程的方式是「恢复为当前数据集」（复制进上传槽位，原归档不变）。
- **三种状态**：已评分 / 未评分（无 D3 或输入不可解析）/ 仅生成。

> 生成准确率高但覆盖率低 = "做得准但不全"；反之 = "做得全但不准"。两个数必须一起看，只报一个会被追问。
>
> 模式 A 的输入是扫描件（文本层 0 字符），会显示「本次不可评测」而不是 0% —— 这是输入不可解析，不是系统判错，需要可解析文档或 OCR。

**评测对象：只有 P6 产物（P7 不生成标准）**

- P7 读 P6 已落盘的标准 JSON（`deliverables/shared/standards/`），只做比对与计分，**不重新生成**；
- **D3 硬门槛**：D3 未上传、未选择「采用内置数据」或在本轮被关闭（off）时，P7 直接返回「未提供预期输出，无法评测」，**不出任何指标**，也不会回落到内置答案；
- 没有产物就直说「请先在 P6 生成标准」，不会再自己算一份；
- 标准里记录了生成时的**输入快照**（文件名列表），评测时会比对：一致显示「同一批输入生成」，不一致显示「不同批数据」，旧产物无快照显示「无法确认」；
- 开发期如需核对“同一份输入重算是否与产物一致”，用离线脚本 `python -m tools.consistency_check`（不暴露在界面）。

### 3.2 P6 怎么用（含完整模型表格导出）

1. **入口 A**：读取 P4 立项清单 → 生成标准草案；**入口 B**：读取 P5 合成模型 → 生成正式条目。
2. 生成后可在「标准字段表」里补全 `INCOMPLETE` 字段，再执行演化匹配。
3. **下载完整模型表格**：入口卡片旁的「下载完整模型表格」，或标准概览中的「完整模型」按钮，得到 xlsx：

| 工作表 | 内容 |
|---|---|
| 对象类 | 13 列（ID / 编码 / 名称 / 定义 / 父类 / 状态…）|
| 对象类属性 | 24 列（关联ID / 属性ID / 单位 / 类型 / 约束 / 主键 / 可空 / 唯一…）|
| 属性 | 20 列（属性大池子，同名属性复用同一 ID）|
| 说明 | 导出元信息、ID 规则、留空项 |

> ID 规则按 `规则.md`：**对象类ID** = 大类缩写 2 位 + 6 位数字；**属性ID** = `Attr` + 6 位；**关联ID** = 对象类ID + 属性ID。编码缺失时用 `OC` 临时前缀并备注「编码待分配」；业务未填且无生成规则的字段一律留空，不编造。

## 4. 推荐演示动线（约 10 分钟）

### 4.0 开场前 30 秒：证明真的在用大模型

P5 顶部点「模型连通性自检」→ 显示 `qwen3.8-max（2.5s）回显「连通」`。
评委常有"是不是规则引擎套壳"的疑问，这一下先把这个问号消掉；`deliverables/llm/trace.jsonl` 里每一条调用都能对上。

### 4.0.1 内置演示数据集：断网也能把 P0→P7 点完

P0 顶部有一张浅紫色的「内置演示数据集」卡（`模式 B · 大宗材料类-型钢`）。

- **P0 自动装载**：点「载入内置演示数据」后，`data/_presets/型钢-B/p0/` 里的三件套
  （`大宗材料类-型钢.xlsx`、`数据模型-大宗材料类-EM4型钢.xlsx`、`规则.md`）会直接进入上传槽位，
  不需要现场拖文件；进程重启后仍是这个状态（演示机免手动）。
- **每个按钮都是回放**：P1–P7 的计算型接口（`/api/parse`、`/api/extract`、`/api/graph/build`、
  `/api/requirement/*`、`/api/standard/generate`、`/api/evolve/analyze`、`/api/eval/run`）
  按「接口 + 请求体」命中 `data/_presets/型钢-B/trace/` 里的**真实响应**并逐块吐回去 ——
  连大模型的置信度裁决理由一起回放，不联网、不重算。
  实测：P3 底座构建 32.3s → 0.5s，P5 澄清推断 78s → 0.1s，P7 评测 0.6s → 0.03s。
- **产物快照**：`snapshot/` 存图谱、标准、最终模型、评测报告（26 个文件 / 67.5MB），
  激活时铺进工作目录，所以 P3 画布、P6 标准、P7 指标都是"真的在那儿"。
- **不污染用户数据**：激活时先把会被覆盖的文件备份到 `_backup/<时间戳>/`，
  点「退出演示，还原我的数据」按 `restore.json` 逐个还原；
  **在 P0 上传自己的文件会自动退出演示态**（`on_user_upload()`），缓存立刻不参与任何请求。
- **怎么重新录一遍**：`data/` 与 `deliverables/` 处于想录的状态时，跑
  `.venv/Scripts/python.exe backend/demo_capture.py`（会打开录制 → 按 P1→P7 真跑一遍 →
  存快照 → 激活）。只想补某一阶段：`--only p2` / `--from p5a`。
- **P3 类间关系分析按钮也不会真跑**：它要 26 批 × 3~6 分钟的模型调用，
  演示态下直接回放 `data/graph/class_relations_B.json` 里那次真实分析的结论
  （182 条候选 / subClassOf 144 · associates 22 · partOf 16），并标注「本次未调用模型」。
- **P4 不在缓存里**：P4 属于模式 A，要 D1 文档；本数据集只有 B 的数据，
  点 P4 会如实提示「D1 未提供」，和真实运行时完全一致（不是缓存缺失）。
- **诚实标注**：卡片上写明「已录阶段 N 个 / 录制于 时间 / P2 置信度裁决 N 条」，
  回放不是现场计算，界面上不装作现场算了。

### 4.1 开场：从上传开始（P0，2 分钟）

1. 打开页面，停留在 **P0**。
2. 在「① 模式选择」里点选 A 或 B 卡片。
3. 在「② 数据接入（现场上传）」中，把准备好的文件拖入对应槽位 → 点「上传并校验」。

> 若现场不便准备文件，可直接点「全部采用内置数据」，系统回落到 `data/` 下的内置示例集，同样能完整演示。

### 4.1.1 P3 图谱怎么读（2026-10-24 定稿）

| 要看的 | 规则 |
|---|---|
| **三层节点** | `object_class` 对象类 → `field` 对象类属性（一行一条，不跨类合并）→ `attribute` 属性池（按 `属性ID` 归并，被多个类共用）。三类边：`subClassOf` 父子、`hasAttribute` 归属、`refersTo` 取用 |
| **画布只画三类** | 对象类 / 对象类属性 / 属性池。抽取候选（`candidate`）是 P5 匹配的中间产物，**不上画布**（接口也不再下发给画布，只在统计里给数量） |
| **两种来源** | 标准库 = D0 上传入库（`origin=d0`，中性石板灰蓝实心圆，**不标置信度**，表示已人工确认）；增量 = 本轮 D1/D2 抽取（`origin=input`，按证据五档上色的实心圆，强弱用图例里的五个小圆点表示，图上不写档位编号） |
| **画布只画关系网络** | 只有**带类间关系**（`subClassOf` / `partOf` / `associates`）的对象类才上画布。没有关系的类一律不画——几百个孤点平铺既看不出结构，也不是知识图谱该有的样子；这些类在左侧「对象类清单」里照旧可查。一条关系都没有时画布留空并给一句引导，**不提供任何平铺入口** |
| **形状** | 对象类是**实心正圆**（直径按类名字数开方增长，连接度越高再放大一档，形成「核心—边缘」层次），类名标在圆外下方（白底 72% 透明，长名省略号，悬浮出全名 + 关系数 + 属性数 + 证据档位）。不再是白底矩形卡片 |
| **聚焦视图** | 点任意圆点：该类 + 它的前 24 条对象类属性 + 属性池，再点一次或「回到关系全景」返回 |
| **布局** | 固定**力导向**（离线内置三件套 `layout-base.js` → `cose-base.js` → `cytoscape-fcose.js`，缺了退回内置 `cose`），`packComponents: false` 让 41 个天然簇聚成一张图而不是摊成棋盘。初始缩放下限 0.72（保证字能读），「适应画布」一键看全貌 |
| **业务域已删除** | 没有 domain 节点、没有 `belongsToDomain` 边、没有同心圆布局 |

#### 类间关系：为什么图上一条都没有，以及怎么补（2026-10-24 新增）

底座里的 `subClassOf` 只有一个来源——类表的「父类 / 父类ID」列。D0 类表该列全空、D2 需求表本身没有层级列，所以建出来的图是 **380 个类平铺、0 条类间边**。规则抽不出来，只能让模型读内容判断归属：

| 环节 | 规则 |
|---|---|
| **输入** | 每个对象类喂「类名 + 定义 + 属性清单 + 出处证据（如 `T1 表格行·规格齐全`）」，外加一份**全量类名白名单**（当前 380 个）供模型挑父类 |
| **输出** | 只允许四种关系：`subClassOf`（上下位 is-a）、`partOf`（组成 part-of）、`associates`（业务关联）、`sameAs`（同义）。每条必须带 `basis`（判断依据）与 `confidence` |
| **硬校验** | head/tail **必须原样在类名白名单内**（模型编的类直接丢弃并计数）；禁自环；同对类只留一条；无依据（basis < 4 字）丢弃；未知关系类型丢弃 |
| **只产候选** | 分析结果落 `data/graph/class_relations_{A\|B}.json`，**不自动写图**。P3 面板列出候选（类型 / head → tail / 依据 / 置信度 / 是否已入图） |
| **入图** | 人给阈值（默认 0.60）+ 类型白名单点「应用 N 条到图谱」：去重 → **防环**（`subClassOf`、`partOf` 各自按类型查环，跨类型不算环）→ `graph_upsert` 写边 → 重导 OWL（`partOf`/`associates`/`sameAs` 落成 `owl:ObjectProperty`，`partOf` 声明 `TransitiveProperty`、`associates`/`sameAs` 声明 `SymmetricProperty`） |
| **可撤销** | 「撤销 AI 推断关系」只删 `source_ref = llm:class_relations` 的边，原有骨架与节点一律不动 |
| **画布区分** | 表格里本来就有的父子 = 灰色实线；模型推断的父子 = **蓝色虚线**；组成 = 绿色实线 + v 形箭头（部件 → 整体）；业务关联 = 橙色点线无箭头。图例里三种线都有 |
| **降级** | 模型不可用时按钮报「未配置 / key 无效」，不会拿规则结果冒充模型产出；单批失败只记在 `failed_batches`，其余批次照常汇总 |

### 5.2 校验与取数优先级

- **校验不是看扩展名**：xlsx 会定位实际表头并统计规模；PDF 用 pdfplumber 探文本层；JSON 检查必需字段。
- **每个槽位都有滑动开关**：右滑绿色=本轮参与，左滑灰色=不参与（不显示详情、不提示上传、不参与校验）；**必须项（D2 / D4）开关锁定在右侧**，不可关闭。
- **参与后还要选来源**：上传文件，或点该行的「采用内置数据」。**系统不默认替你选内置** —— 未选来源标「待选择来源」，此时相关环节直接拒绝执行并说明原因。
- 顶部「全部采用内置数据」= 一键把所有项设为内置（适合快速演示）；单项开关只影响自己。
- **槽位彼此独立**：可以只上传 D2、其余采用内置；单个槽位的「采用内置数据」只清自己。
- **上传后自动清缓存**，上传建模集还会**自动重建该模式图谱**。

**取数铁律：没有显式选择 = 拿不到数据，绝不隐式回落内置。**
后台取数（`upload_manager.active_files / active_path`）只看槽位决策：`uploaded` 给上传文件、`builtin` 给内置文件、`off` / `未选择` 一律返回空并抛 `DataUnavailable`。
于是所有环节都是"要么用你选的数据，要么明确报「数据未就绪」，不存在第三种可能"。

| 环节 | 实际读取 | 未选择时的表现 |
|---|---|---|
| P1 解析 | D1（A）/ D2（B） | 拒绝执行，提示缺哪一项 |
| P2 抽取 | D1 / D2 + D0（已有标准库，可为空） | 拒绝执行 |
| P3 知识底座 | **D0 已有标准库 + 本轮输入**（A：D1 / B：D2），**不读 D3** | 拒绝执行 —— 底座不再取自预期输出 |
| P4 发现式梳理 | D1 + D0 | 拒绝执行；D0 为空时新颖性一律判「全新」并注明 |
| P5 解析 / 完备性 / 合成 | D2 + D4 | 拒绝执行 |
| P6 生成（入口 B） | D2 | 拒绝执行 |
| P7 评测 | D3 | 拒绝执行，不出任何指标 |

- 想全部重来：P0 顶部「全部采用内置数据」把 8 项都设为内置；要回到"未选择"状态就逐个点掉（或清空上传）。

### 5.3 防泄漏告警

上传建模集时，系统会把它与**同模式**的「预期输出」答案集比对。若对象类重合 ≥ 50%，槽位会出现**红色泄漏告警**——说明你正在把"考题答案"当建模数据使用。

> 只与同模式比对。跨模式的高重合是正常的（EM4 对 A 是答案、对 B 是建模集）。

## 6. 双模式隔离与硬指标

### 6.1 隔离规则（硬约束）

| 模式 | 知识底座允许的供给 | 硬禁来源 |
|---|---|---|
| **A** | D0 已有标准库 + `D1` 本轮文档 | `D3 预期输出`、`modeB/**`、`full_mode`、`dev_model` |
| **B** | D0 已有标准库 + `D2` 需求表 | `D3 预期输出`、`modeA/**`、`full_mode`、`dev_model` |

- 所有工具统一从 `backend/tools/mode_isolation.py` 取数，命中禁用来源直接抛错，不静默放行。
- **P3 底座唯一入口是 `backend/tools/base_supply.py`**：只装配 D0 + 本轮输入，出口带 `supply` 块（D0 数量 / 输入数量 / 来源分布 / 政策原文），面板照此展示。
  D3 只用于 P7 评分，**不得**作为底座输入——否则模型就是拿答案建库、再由答案打分（循环论证）。
- 两模式图谱**节点集合交集必须为 0**（当前实测为 0）。

### 6.2 知识底座三维度指标

| 模式 | 对象类 | 属性 | 关系（subClassOf + hasAttribute） | 当前实测 |
|---|---|---|---|---|
| **A** | ≥ 100 | ≥ 100 | ≥ 60 | **357 / 23944 / 23944** ✔ |
| **B** | ≥ 20 | ≥ 200 | ≥ 500 | **420 / 24795 / 24795** ✔ |

> 这三个阈值是**规模参考线**（用来判断"底座是不是空转"），**不代表正确性**——正确性只由 P7 的分层指标说话。
> 模式 A 的规模主要来自 D0 常驻库：本轮 D1 两份 PDF 均为扫描件（文本层 0 字符），输入供给为 0，面板会显式标注这一点。
> 已知残缺：D0 的类表未给父类列，导致 `357/357 个对象类无父类`，A 模式建不出 `subClassOf`（不是 0 条"因为算法没跑"，而是"供给里就没有"）。

### 6.3 关系层指标（2026-10-23 新增）

原来只评到对象类层、属性层，关系抽取是"做了但没量"。现在补齐：

- **抽取侧** `backend/tools/relation_extractor.py`：`subClassOf`（父类ID / 标题层级 / 句式）、`hasAttribute`（属性表行 / 归属列）、`associates`（线索型，不计分），每条关系带 `evidence`（文件 + 表 + 行/列）。
- **评测侧** `evaluator.py::_eval_relation_layer`：按 `(类型, 头实体, 尾实体)` 三元组比对，输出 `per_type`（生成数 / 预期数 / 命中 / 漏 / 多 / 生成准确率 / 覆盖率）+ 漏抽与多出样例。
- **报告**：`deliverables/evaluation/test_report.md` 总览表单列「关系」一行（量纲与合计不同，不并入合计），并新增 `## 关系层` 章节。
- 当前实测（B，5 份需求表）：`hasAttribute` 生成 855 / 预期 891 / 命中 748 → 87.49% 生成准确率、83.95% 覆盖率；`subClassOf` 2 / 52 / 0 → 0%（D0 无父类数据）。关系层合计 857 / 943 / 748 → **87.28% / 79.32%**。

### 6.4 质量评价的第三维：口径准确率

`standard_generator.quality_score()` 原来 `accuracy` 恒为 `None`，只剩完整性、规范性两维。现在：

- 逐字段机检**数据类型合法**（对照允许类型集）与**约束可解析为技术格式**（正则判定，空值即不通过）。
- 输出 `accuracy` / `accuracy_basis`（`machine` 或 `human`）/ `accuracy_checked`（通过数、总数、失败项明细）。
- 实测（B，855 字段）：2262/2645 = **85.5%**，失败项集中在「约束可被解析为技术格式」383 条——空约束不再被"跳过"而是判失败，避免 100% 的假象。

### 6.5 检索口径：本地向量 + 多跳路径

| 位置 | 原来 | 现在 |
|---|---|---|
| `rag_vector`（P4 新颖性 / P5 匹配 / P6 演化） | Dice 字符二元组字面相似 | `local_embedding.py`：字 n-gram TF-IDF → 随机投影 1024 维 → L2 归一化 → 余弦 |
| `rag_graph`（P5 / P6 / P3 查询） | 同名节点查一遍（等于字典查找） | `graph_query`：稀疏 TF-IDF 倒排 + 对象类向量召回 → 按边类型加权的多跳 BFS（衰减 0.55）→ 输出 `paths` |

- **诚实标注**：这是**本地随机投影嵌入（LSA 家族近似）**，不是预训练语言模型；接口 `retrieval_impl` 会照此返回，面板文案不得写"预训练 embedding"。
- 同名精确命中的余弦会被定义文本稀释（`备注` vs `备注` 只有 0.28），因此索引对**精确同名**直接给 1.0。
- 阈值：`landscape_analyst.VECTOR_THRESHOLD = 0.35`（噪声底 ≈ 0.15）。低于阈值只作"最近邻参考"，不算命中已有标准。

## 10. 常见问题

**页面显示大量 `{{ }}`、按钮点击无反应？**
说明 Vue 没有挂载。检查是否通过 `http://127.0.0.1:8123` 访问（而非双击 html 文件），并访问 `/vendor-status` 确认 `ok: true`。

**启动报端口被占用？**
8123 已被其他程序占用。关闭占用进程，或修改 `backend/main.py` 末尾的 `port`。

**上传被拒绝？**
系统做的是真实结构校验：xlsx 必须能定位到对象类/属性表头，PDF 必须能打开，JSON 必须含规定字段。仅改扩展名无法通过。

**扫描版 PDF 解析结果是 `degraded`？**
正常现象。扫描件无文本层，只能按文件名主题与参考库弱匹配，置信度整体偏低。这恰好用于演示「低质量输入 → 降级 → 人工门控」链路。上传时建议保留业务原名，文件名会参与主题推断。

**P4 为什么没有「语义相近可复用」或「口径冲突」标签？**
新颖性相似度阈值锁定 0.62，不为了凑齐四色而调低。模式 A 隔离后最高相似度仅 0.46，因此实际只出现 `novel / covered / conflict` 中的若干种，属诚实结果。

**大模型在哪几个环节用？为什么不是全部？**
只用于"必须理解/生成自然语言"的四件事：P2 术语归一与定义补写、P4 新颖性语义判断与立项优先级、P5 缺失字段定义补写、P6 属性定义补全。对齐、计分、ID 生成、阈值判定等仍走规则 —— 模型参与计分会让准确率不可复现。

**跑到一半想停下来怎么办？**
顶部进度条右侧有「停止」按钮：中断当前请求、复位所有按钮，并给一条「已停止」回执。服务端可能还在收尾，建议等 3–5 秒再重试，避免两个任务并发。

**点了 P2 / P4 之后界面像卡住了？**
这两个面板会真实调用模型，首次要 40–100 秒。点下去后界面会先显示「大模型：…（约 60 秒）」，不是卡死。跑完结果进缓存，再点秒回；**重启服务会清缓存**，演示前建议先跑一遍预热。

**模型报 401 / 402 / 超时怎么办？**
401 是 key 不对，402 是账户余额不足，超时是单批太大。三者都会自动回落规则并在界面写明原因，不会阻塞流程；`/api/llm/status` 可以看到具体原因和 key 末四位。

**P0 顶部那块深色的「D0 已有标准库」是什么？**
它不是本轮数据，是长期复用的存量标准库。P4 新颖性、P5 匹配、P6 演化**只读它**；库为空时不顶替——新颖性一律判「全新」并在面板注明，不会拿评测答案当库。上传时若与 D3 预期输出重合度过高会告警。生成的标准要勾选「通过并入库」才会写回。

**演示数据想恢复初始状态？**
P0 点「全部采用内置数据」。

## 11. 已知限制（诚实标注）

| 项 | 状态 | 说明 |
|---|---|---|
| D1 业务文档 | degraded | 内置示例是扫描件（文本层 0 字符），抽取候选全部低置信；换可解析文档即恢复 |
| 真实已有标准库 | D0 常驻库 | 比赛拿不到真实存量标准；改为「P0 上传一次长期复用」（当前 357 类 / 23944 属性 / 1523 个字段名）。库为空时**不顶替**：新颖性一律判「全新」并在面板注明，不用评测答案冒充 |
| P3 底座来源 | **已解耦** | 只经 `base_supply` 取 D0 + 本轮输入，不再读 D3；`supply` 块如实列出 D0 与输入各自贡献 |
| D0 父类列缺失 | 数据残缺 | D0 类表未给父类列（父类ID 值不在表内），`357/357 个对象类无父类` → 模式 A 建不出 `subClassOf`；不编造父类，面板照实标 |
| 类名写法差异 | **已归一** | 同一对象类在不同表里「全角（）/半角()」写法不同，曾被当成两个类（对账差 17 行）。现在读取时统一抹平排版差异（`text_norm.canonical_name`），查重仍用更激进的 `norm_key` |
| D3 预期输出（可选） | **ready** | 三表直接作规范标准；用户梳理新数据时通常没有，缺席只影响评分不影响生成 |
| D5 需求模板 | ready | 不上传也能按列自动定位 |
| 模式 A 参考底座 | **已下线** | 不再"当前数据集不够就拿备用样本凑"——底座要么有供给、要么明确报不可用 |
| 本地向量 | 非预训练模型 | 字 n-gram TF-IDF + 随机投影，同义/近义靠字面重叠与上下文近似；「弯头」这类库内没有对应词汇的查询仍会给出较弱结果，面板按「低于阈值仅作参考」处理 |
| 多跳召回 | 含弱关联 | 2 跳会带回"同类的兄弟属性"（得分约 0.098），它们在语义上只是相关不是同一口径；路径与 `via` 全部展示，由人判断 |
| D2 需求表 | 必须 5 份 | 5 份大宗材料表要**全部**在 D2 槽位（实测 895 行 → 去重 855 字段）。只传 1 份时覆盖率会掉到 19.8%，容易被误读成模型差；换机器/重装后务必核对 P0 的 D2 文件数 |
| P4 新颖性 | conflict = 0 | E板块自身无「同名不同口径」属性；冲突演示由模式 B 承载 |
| P6 模式 A 可使用率 | 33.3% | 隔离后管道管件候选在 E板块查不到编码/约束，`INCOMPLETE` 偏多，不粉饰 |
| 模式 A 评测 | **不可评测** | 输入为扫描件（0 字符文本层），无法生成；标 `evaluable=false`，不显示 0% |
| P7 | **可用** | 四块指标（对象类 / 属性 / 关系 / 合计）+ 归因 + 报告 + CSV；关系层 `subClassOf` 目前 0/52（D0 无父类数据支撑），如实展示不粉饰；三维雷达图与 ZIP 导出待补 |
| 大模型时延 | 不可控 | 单批 12 条约 20–40s、8 条语义判断约 40s，网络差更久；已加超时、并发、缓存与"先显示进度"，但**无法做到秒出** |
| 扫描件正文抽取 | 未启用 | A 内置文档无文本层，模型无原文可抽，`llm.skipped_extract` 如实标注；需先 OCR 才能"带证据抽取" |
| P8 | 未独立交付 | 仅 P1 / P2 底部有门控队列预览 |
